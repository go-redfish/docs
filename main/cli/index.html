Command-line reference

The redfish command: sessions, raw requests, systems, and a mock BMC.

The redfish command ships with the module since v0.3.0. It is a cobra command tree with POSIX flags and --help on every command. Results go to standard output and errors to standard error. This page follows the --help of v0.11.0.

go install github.com/go-redfish/redfish/cmd/redfish@v0.11.0

Global flags

FlagMeaning
--endpointthe BMC’s address, https://host[:port]
--useruser name
--password-filefile holding the password (mode 0600)
--sessionuse the session saved by redfish session login instead of the password
--ca-filePEM file of the CAs that sign the BMC’s certificate (default: the system roots)
--insecuredo not verify the BMC’s certificate; prints a warning on stderr and cannot be combined with --ca-file
--timeoutper-request timeout (default 10s)
-o, --outputjson (default) or table

There is no password flag and no password environment variable. The password is read from a file, so it never appears in a process listing or a shell history.

session

CommandWhat it does
redfish session loginlogs in with --user and --password-file by POSTing to the Sessions collection (DSP0266 13.3.4). The X-Auth-Token is saved in a 0600 file under the user’s config directory and is never printed
redfish session statussays whether a session is saved for --endpoint
redfish session logoutends the saved session at the BMC and removes its file
redfish session listlists the active sessions of the service (v0.7.0)
redfish session clearends every active session of the service, its own last (v0.7.0)
redfish session configchanges SessionService properties (v0.7.0)

Afterwards, pass --session to any command instead of --user and --password-file.

raw

redfish raw sends one request to a path of the service (/redfish/...) and prints the body.

CommandRequest
raw get PATHGET a resource
raw head PATHHEAD: status and headers (ETag)
raw patch PATH --data … [--if-match ETAG]PATCH properties; a stale --if-match is answered 412
raw put PATH --data …PUT: replace a resource
raw post PATH --data …POST: create a member or invoke an action
raw delete PATHDELETE a resource

--data is the JSON body: the text itself, @file, or - for standard input. A 202 answer names a task monitor: the monitor is printed on stderr and the Task body on stdout. A non-2xx answer is an error that carries what the service said: its code, its message and @Message.ExtendedInfo.

mock serve

redfish mock serve starts the mock BMC over HTTPS. It uses a self-signed certificate valid for 24 hours, writes that certificate to --ca-out (pass it back as --ca-file), prints the endpoint and stops on interrupt.

FlagMeaning
--listenaddress to listen on (default 127.0.0.1:0, a free loopback port)
--ca-outwhere to write the certificate (default: under the user config directory)
--mock-password-filefile holding admin’s password; without it the password is password
--task-pollshow many times a task monitor answers 202 before the task completes (default 2)

Example 

redfish mock serve --ca-out ./mock-ca.pem &        # prints https://127.0.0.1:PORT
printf 'password' > pw && chmod 600 pw
E=--endpoint=https://127.0.0.1:PORT
redfish $E --ca-file ./mock-ca.pem --user admin --password-file pw session login
redfish $E --ca-file ./mock-ca.pem --session raw get /redfish/v1/Systems
redfish $E --ca-file ./mock-ca.pem --session systems power PowerForceOff
redfish $E --ca-file ./mock-ca.pem --session session logout

systems

Since v0.4.0, redfish systems drives the ComputerSystem resources: the Systems commands of the Ansible modules redfish_command, redfish_config and redfish_info. When the service has several systems, --id names the one to use (the last segment of its path). Without --id, such a service gets an error that lists the systems.

CommandWhat it does
systems listlists the systems (their paths)
systems powerPowerOn, PowerForceOff, PowerForceRestart, PowerGracefulRestart, PowerGracefulShutdown, PowerReboot, PowerCycle, PowerFullPowerCycle, each checked against the ResetType values the service allows
systems boot-overridethe boot source override: get, set, disable
systems boot-orderthe boot order: get, set, default
systems biosBIOS attributes: get, set (through @Redfish.Settings), verify, reset, registry
systems secure-bootUEFI Secure Boot: enable, disable
systems power-restore-policyget, set
systems ledthe system’s indicator LED: on, off, blink
systems asset-tagsets AssetTag
systems inventorysystem, cpu, memory, nic, psu
systems healththe health of the system and its subsystems
systems logsthe entries of the system’s log services, and logs clear (v0.6.0)
systems virtual-mediaget, insert, eject (v0.6.0)

Each command’s flags are in its --help.

chassis

Since v0.5.0, redfish chassis reads and drives the Chassis resources: the Chassis commands of the Ansible modules redfish_command and redfish_info. --id names one chassis (the last segment of its path). Like the Ansible modules, the reading commands (inventory, fans, power, thermals, psu, health, hpe) cover every chassis when no --id is given. The other commands act on one chassis: the only one, or the one --id names. Without --id, a service with several chassis gets an error that lists them.

CommandWhat it reads or does
chassis listlists the chassis (their paths)
chassis inventorythe identity of the chassis (GetChassisInventory)
chassis powerPowerControl of the Power resources (GetChassisPower)
chassis thermalstemperatures of the Thermal resources (GetChassisThermals)
chassis fansfans of the Thermal resources (GetFanInventory)
chassis psupower supplies present (GetPsuInventory)
chassis healththe health of the chassis, its power supplies, fans and PCIe devices (GetHealthReport)
chassis ledthe indicator LED: on, off, blink
chassis sensorsthe Sensor resources (Sensors collection)
chassis power-subsystemPowerSubsystem and its power supplies
chassis thermal-subsystemThermalSubsystem, its fans and ThermalMetrics
chassis metricsEnvironmentMetrics: power, energy, temperature, fan speeds
chassis hpeHPE OEM settings covered by the Ansible modules: thermal-config, fan-percent-min

The Power and Thermal resources are deprecated in favour of PowerSubsystem, ThermalSubsystem and Sensors, but many BMCs still serve only them, so the command reads both.

managers

Since v0.6.0, redfish managers drives the Manager resources (the BMC itself): the Manager commands of the three Ansible modules. inventory, health and nic get cover every manager when no --id is given. The other commands act on one manager: the only one, or the one --id names.

CommandWhat it reads or does
managers listlists the managers (their paths)
managers inventoryidentity and firmware (GetManagerInventory)
managers healththe health of the managers
managers powerPowerGracefulRestart (alias GracefulRestart), PowerOn, PowerForceOff, PowerForceRestart, PowerGracefulShutdown, PowerReboot; --wait blocks until the service answers again (--wait-delay, --wait-timeout)
managers reset-to-defaultsResetAll, PreserveNetworkAndUsers, PreserveNetwork
managers network-protocolsthe network services (HTTP, SSH, IPMI…): get, set
managers ntp setthe NTP service
managers datetimethe date, time and UTC offset: get, set
managers nicthe manager’s network interfaces: get, set
managers host-interfacethe host interfaces: get, set
managers service-idServiceIdentification: get, set
managers logsthe entries of the log services, and logs clear
managers virtual-mediaget, insert, eject

managers virtual-media insert --image URL puts the image in the first free slot that supports one of the --media-type values. It uses the InsertMedia action when the slot has one, else a PATCH. Nothing is sent when the image is already inserted. The password to fetch the image is read from --image-password-file (mode 0600), never given on the command line.

v0.6.0 also added systems virtual-media (get, insert, eject) for services that attach virtual media to the system, systems logs (entries and clear) and chassis logs.

accounts

Since v0.7.0, redfish accounts drives the AccountService: the Accounts commands of redfish_command and the ListUsers and GetAccountServiceConfig commands of redfish_info. An account is named by its user name, or by --id (its Id).

CommandWhat it does
accounts listthe accounts, without the empty slots (ListUsers)
accounts add USERNAMEcreates the account; nothing is done when the user exists (AddUser)
accounts delete USERNAMEdeletes the account; nothing is done when it does not exist (DeleteUser)
accounts enable, disableEnableUser, DisableUser
accounts passwordsets the account’s password (UpdateUserPassword)
accounts renameUpdateUserName
accounts rolesets RoleId (UpdateUserRole)
accounts typessets AccountTypes and/or OEMAccountTypes
accounts rolesthe roles of the service
accounts config [set]shows the AccountService (GetAccountServiceConfig) or changes it

A new password comes only from --new-password-file (mode 0600) or --new-password-stdin. No flag takes it and no environment variable is read. It is never printed, and an error from a service that echoes it back is redacted. Some services have a fixed number of account slots and refuse POST and DELETE. On those, like the Ansible modules, add fills an empty slot (or the one --id names) with a PATCH and delete empties the account.

update

Since v0.8.0, redfish update drives the UpdateService: the Update commands of redfish_command and redfish_info.

CommandWhat it does
update simpleasks the BMC to fetch an image and update with it (SimpleUpdate)
update pushuploads an image to the MultipartHttpPushUri, streamed from the file (MultipartHTTPPushUpdate)
update statusthe status of an update: its task or job (GetUpdateStatus)
update operationsperforms what the update asks for to continue: its resets (PerformRequestedOperations)
update inventory [--software]the firmware inventory, or the software inventory
update capabilitieswhat the service can do: multipart push, actions, transfer protocols

simple and push start a task. Its monitor is printed on stderr and not awaited, like redfishtool’s -N. Add --watch to follow the task to its end; progress goes to stderr. push accepts only a regular file and refuses one larger than --max-size (4 GiB by default) before it sends anything. The image is streamed, never loaded whole into memory. The image server’s password comes from --image-password-file (mode 0600) or --image-password-stdin. A password written inside the image URI is refused.

storage

Since v0.9.0, redfish storage drives the storage of a system: GetStorageControllerInventory, GetDiskInventory and GetVolumeInventory of redfish_info, and CreateVolume and DeleteVolumes of redfish_config. --id picks the system, as for systems.

CommandWhat it reads or does
storage controllersthe storage controllers
storage disksthe drives of each controller, from Storage, or from the older SimpleStorage when the system has no Storage
storage volumesthe volumes of each controller
storage volume create --storage IDcreates a volume: --raid-type, --drive (repeatable), --name, --capacity-bytes; the RAID type and the drives are checked against the controller before anything is sent
storage volume delete --storage ID VOLUME_ID...deletes the volumes named

Deleting a volume destroys its data, so volume delete deletes only the volumes it is given by name. It has no option to delete all of them. It prints the paths on stderr before the first deletion. If one name is not a volume of the subsystem, nothing is deleted. --dry-run prints the paths and deletes nothing.

With v0.9.0 every command of the three Ansible modules has its function and its command: see Parity.

events

Since v0.10.0, redfish events drives the EventService. This goes beyond the Ansible modules, and the reference is the Redfish specification itself: DSP0266 1.23.0, section 12.1 (eventing) and section 12.5 (server-sent events).

CommandWhat it does
events statusreads the EventService: whether it is enabled, its SSE URI, and the formats, registries, resource types and SSE filters it supports
events subscriptionslists the subscriptions, or shows one
events subscribe --destination URLcreates a subscription, so the service POSTs events to that URL
events unsubscribedeletes a subscription
events test --message-id IDsubmits a test event (SubmitTestEvent)
events listenopens the SSE stream and prints events as they arrive, until Ctrl-C or --count

subscribe checks its filters (--registry-prefix, --resource-type, --message-id, --origin…) against what the service supports before it sends anything. The destination must be an https URL with no credentials, query or fragment. The service sends HTTP headers with every event, usually an Authorization header for the receiver, and those headers are credentials. So they come from --headers-file (mode 0600) or --headers-stdin, never from a flag, and are never printed.

listen prints one JSON line per event with -o json. --filter is passed as the stream’s $filter (for example --filter "MessageId eq 'Contoso.1.0.TempAssert'"), and the service applies it. The stream is bounded: a line or an event larger than --max-line or --max-event-bytes (1 MiB each by default, DSP0266 12.1.2) ends it with an error. After a broken connection, listen reconnects up to --reconnects times, resuming with Last-Event-ID. An end by the service, a Ctrl-C or --count ends it cleanly.

redfish $E --session events listen --count 1 &
redfish $E --session events test --message-id Base.1.0.Success
# {"event":{"@odata.type":"#Event.v1_6_0.Event","Events":[{"EventId":"1","MessageId":"Base.1.0.Success",…}],…},"id":"1"}

certs

Since v0.11.0, redfish certs drives the CertificateService. It follows DSP0266 1.23.0 sections 9.9.13 and 13.1.3, and the CertificateService 1.2.2, Certificate 1.11.0 and CertificateLocations 1.0.4 schemas.

CommandWhat it does
certs statusreads the CertificateService: its locations resource and the actions it has
certs listlists every certificate the service holds (CertificateLocations)
certs show ID|PATHshows what the service says about a certificate, and what the certificate itself says: subject, issuer, validity, key and usages, decoded with crypto/x509
certs csr --collection PATHmakes a certificate signing request (GenerateCSR) and writes the PEM to stdout or to a new file given with --out
certs installadds a certificate to a collection (POST)
certs replaceputs a certificate in place of another (ReplaceCertificate) and prints the new one’s path
certs deleteremoves a certificate
certs rekey, certs renewmake a CSR from an existing certificate, with a new key pair or with the same one

A certificate signed from one of the service’s own CSRs needs no private key. For any other certificate, the key comes from --key-file (mode 0600) or --key-stdin. It is checked against the certificate before anything is sent, and it is never printed: an error that contains it is redacted. A certificate string that already contains a private key is refused, so that the key can only reach the BMC through that path. Passwords (the CSR challenge password, a PKCS#12 password) come from 0600 files, never from a flag.

redfish $E --session -o table certs list
redfish $E --session certs csr --collection /redfish/v1/Managers/BMC/NetworkProtocol/HTTPS/Certificates \
  --common-name bmc.example.org --out bmc.csr
# csr: subject CN=bmc.example.org, ECDSA P-256, signature valid: true
